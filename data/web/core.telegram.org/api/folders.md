# Dialog folders


Telegram allows placing chats into folders, based on their type, mute status, or other custom criteria, thanks to folder blacklists and whitelists: these folders may also be shared with other users.

In the API, folders are called "dialog filters".  
In the UI, folders are typically represented as tabs.  

On startup, clients call:

- [messages.getDialogFilters](/method/messages.getDialogFilters.md) to fetch a list of previously configured folders.
- [messages.getSuggestedDialogFilters](/method/messages.getSuggestedDialogFilters.md) to fetch a list of suggested folder combinations.
- [help.getAppConfig](/method/help.getAppConfig.md) to fetch app-specific configuration parameters.  

The boolean under the [`dialog_filters_tooltip` JSON key](/api/config.md#dialog-filters-tooltip) in the result of [help.getAppConfig](/method/help.getAppConfig.md) can be used to determine whether a folder tooltip should be presented to the user right away.  
The UI should then show a list of suggested folder combinations.  

Once configuration is finished, apps call [messages.updateDialogFilter](/method/messages.updateDialogFilter.md) to create or update existing folders.  
As per the [dialogFilter](/constructor/dialogFilter.md)/[dialogFilterChatlist](/constructor/dialogFilterChatlist.md) constructors, folders have multiple flags that can be combined to determine which chats should be included in (or excluded from) the folder, which emoji to use as icon for the folder and its name.  
Folders can also have up to `dialogs_folder_pinned_limit_*` pinned chats, as determined by the [client configuration](/api/config.md#client-configuration).

[dialogFilterChatlist](/constructor/dialogFilterChatlist.md) constructors are used to represent imported [shareable folders](#shared-folders).  

To reorder existing folders, [messages.updateDialogFiltersOrder](/method/messages.updateDialogFiltersOrder.md) should be used with the IDs of the various dialog filters.

[Premium](/api/premium.md) users also have access to a [dialogFilterDefault](/constructor/dialogFilterDefault.md) constructor, used only when reordering folders to indicate the default (all chats) folder.  

To delete folders, use [messages.updateDialogFilter](/method/messages.updateDialogFilter.md) without populating the `filter` flag field.  

Clients can receive [updateDialogFilter](/constructor/updateDialogFilter.md), [updateDialogFilterOrder](/constructor/updateDialogFilterOrder.md) updates with new filter information, generated by other clients when modifying folder info.  
Clients can also receive [updateDialogFilters](/constructor/updateDialogFilters.md), in which case folder info should be refetched manually using [messages.getDialogFilters](/method/messages.getDialogFilters.md).

Folder tags may be enabled or disabled for all [folders](#folders) using the [messages.toggleDialogFilterTags](/method/messages.toggleDialogFilterTags.md) method ([Business](/api/business.md) users only).  

If the new value of the toggle is different, the method will emit an [updateDialogFilters](/constructor/updateDialogFilters.md) to all other currently-logged in sessions, which should trigger a call to [messages.toggleDialogFilterTags](/method/messages.toggleDialogFilterTags.md) to load the new value of the toggle, in [messages.dialogFilters](/constructor/messages.dialogFilters.md).`tags_enabled`.  

If folder tags are enabled, clients should add folder tags (one for each folder the dialog entry is a part of, except for the "All chats" folder represented by [dialogFilterDefault](/constructor/dialogFilterDefault.md) and tags with `color=-1`) to all dialog entries, under the preview of the latest message.  

These folder tags should contain the name of the folder, and should be colored with the `color` specified in the dialog folder entry.  
The color is an integer ranging from -1 to 6; if -1, the tag must not be shown in the dialog list; use red, orange, violet, green, cyan, blue, pink for indexes 0 to 6 (i.e. the same colors used for randomized fallback [message accent colors](/api/colors.md)).

The tag `color` may only be changed if the user has a [Premium](/api/premium.md) subscription and tags are enabled.

Folders may be shared using [chat folder deep links](/api/links.md#chat-folder-links).  
These links are generated by invoking [chatlists.exportChatlistInvite](/method/chatlists.exportChatlistInvite.md), passing the ID of the folder that should be exported, along with a list of `peers` that should be included in the shared folder.  
Only channels and groups/supergroups may be specified in the `peers` array; these channels and groups must be public, or the user must have permission to manage invite links. Basic groups will automatically be [converted to supergroups](/api/channel.md#migration) when invoking the method.  
An optional name for the shared link may also be specified using `title`.  

Use [chatlists.getExportedInvites](/method/chatlists.getExportedInvites.md) to list all links generated for a folder, use [chatlists.editExportedInvite](/method/chatlists.editExportedInvite.md) to edit the title or list of `peers` of a specific link and [chatlists.deleteExportedInvite](/method/chatlists.deleteExportedInvite.md) to revoke an exported link, preventing new users from importing it.  

The maximum number of per-folder invites that can be created by [Premium](/api/premium.md)/non-[Premium](/api/premium.md) users is specified by the `chatlist_invites_limit_default`/`chatlist_invites_limit_premium` [client configuration parameters&nbsp;&raquo;](/api/config.md#chatlist-invites-limit-default).  

Use [chatlists.checkChatlistInvite](/method/chatlists.checkChatlistInvite.md) to obtain information about a chat folder deep link before importing it with [chatlists.joinChatlistInvite](/method/chatlists.joinChatlistInvite.md), specifying in `peers` which channels and groups to join (excluding inaccessible channels/supergroups, i.e. the user may not join a supergroup/channel where they were banned, corresponding to a [channelForbidden](/constructor/channelForbidden.md) constructor).  
If the user can't join any of the `peers` of a folder, the folder can't be imported.

The maximum number of shareable folders that a [Premium](/api/premium.md)/non-[Premium](/api/premium.md) user may join is specified by the `chatlists_joined_limit_default`/`chatlists_joined_limit_premium` [client configuration parameters&nbsp;&raquo;](/api/config.md#chatlists-joined-limit-default).  

Users that import a folder should retrieve additions made to the peer list by invoking [chatlists.getChatlistUpdates](/method/chatlists.getChatlistUpdates.md) at most every `chatlist_update_period` seconds (a [client configuration parameter&nbsp;&raquo;](/api/config.md#chatlist-update-period)).  
If the returned `missing_peers` list is non-empty, the client should present it to the user, who may choose to join all or a subset of them (excluding inaccessible channels/supergroups), passing them to the `peers` parameter of [chatlists.joinChatlistUpdates](/method/chatlists.joinChatlistUpdates.md).  
If after excluding inaccessible peers and peers deselected by the user the `peers` list is empty, invoke [chatlists.hideChatlistUpdates](/method/chatlists.hideChatlistUpdates.md) instead of [chatlists.joinChatlistUpdates](/method/chatlists.joinChatlistUpdates.md).

When removing an imported folder, the list of included peers should be presented to the user prior to deletion, with the peers listed in [chatlists.getLeaveChatlistSuggestions](/method/chatlists.getLeaveChatlistSuggestions.md) already pre-marked for deletion: the user may then choose to delete or keep some or all of the groups and channels of the folder when invoking [chatlists.leaveChatlist](/method/chatlists.leaveChatlist.md) to delete the folder, specifying in `peers` the list of channels and groups from the folder that should also be removed.

### Peer folders

The API also has another method for identifying groups of peers, used by archived chats.

API peer folders are typically used only by [archived chats](https://telegram.org/blog/archive-and-new-design), and are really handy for distinguishing groups of peers, since most peer-related constructors (updates, chat info) will contain the `folder_id` assigned the specified chat.  

In Telegram apps, API peer folders are used only to implement the chat archive, identified by `folder_id` `1`; all other peers are in `folder_id` `0` by default; no other `folder_id` is allowed at the moment.

- [folders.editPeerFolders](/method/folders.editPeerFolders.md) can be used to add and remove peers from peer folders.

Both methods return an [updates](/constructor/updates.md) constructor, containing a single [updateFolderPeers](/constructor/updateFolderPeers.md) with the new `folder_id` of moved peers.  
Clients can also receive [updateFolderPeers](/constructor/updateFolderPeers.md) as a normal [update](/api/updates.md), generated by other clients when modifying peer folders.

Clients can then use [InputDialogPeer](/type/InputDialogPeer.md) to refer either to a specific chat, or to all chats in a peer folder: the server will return a [DialogPeer](/type/DialogPeer.md) in certain constructors for the same purpose.
